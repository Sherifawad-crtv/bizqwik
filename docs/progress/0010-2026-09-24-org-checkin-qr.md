# 0010 — Lifetime check-in QR page (per org)

**Date:** 2026-09-24 · frontend only (ops)

## What changed
A dedicated, printable **lifetime check-in QR** for each gym, generated in the
ops dashboard.

- **`src/routes/ops/OrgQr.tsx`** (route `/bizqwik/orgs/:id/qr`): renders the QR
  (via the new `qrcode` dep) encoding the org's **slug** — its check-in token,
  fixed for the org's life, matching the `/client/check-in` backend contract
  (`token === slug`). A member opens their branded app, taps scan, and scans this
  to check in + earn a point. Actions: **Download PNG** (canvas data URL) and
  **Print / Save PDF** (opens a clean, chrome-free print document — gym name, QR,
  instructions — and triggers the browser print dialog, which offers Save-as-PDF;
  no PDF dependency added).
- **`src/routes/ops/CreateOrgSheet.tsx`**: the create flow now ends on a success
  step ("… is live") with a **View & print check-in QR** button → the QR page,
  plus Done. The org list still refreshes underneath.
- **`src/routes/ops/OrgDetail.tsx`**: a **Check-in QR** section with an Open
  button, so the code is reprintable any time, not only at creation.
- **`src/App.tsx`**: `/bizqwik/orgs/:id/qr` route in the ops group.
- Dependency: `qrcode` (+ `@types/qrcode`).

## Notes / follow-ups
- Payload is the plain slug so the Phase 4 in-app scanner can send the scanned
  value straight through as `token`. If we later prefer a deep-link URL, that's a
  scanner + backend-parse change, not a reprint.
- Currently ops-only (per the onboarding-flow request). Easy to also expose to
  the gym's dept_head later — `OrgQr` only needs the org name + slug.

## Verification
`npx tsc -b` + `npm run build` clean (qrcode bundles).
