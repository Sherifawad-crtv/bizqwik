# 0009 — Money-flow business UI complete (Phase 3, slices 5–8)

**Date:** 2026-09-24 · frontend only (all against edge fn v44)

Wires the v44 money-flow endpoints into the business app. Four UI slices:

- **Front-desk refund** (`Members` client sheet): amount + to-wallet / cash-card
  toggle + note → `POST /clients/refund`.
- **Payment selector** (`PaymentSelect` component) on desk sales: new-client
  create (cash/card), renew membership/package (cash/card/wallet), drop-in
  (cash/card, +wallet when a member is linked). Threads `payMethod` through
  `sellMembership`/`sellPackage`/`createServiceClient`/`dropIn`. Insufficient
  wallet surfaces the backend error inline.
- **Class roster** (`ClassRosterSheet`, shared): mark arrived / no-show and
  collect a pending pay-at-desk booking (cash/card/wallet). Opened by dept_head
  via "View roster" on each class card, and by front desk via a new
  `/desk-classes` screen (a home quick-action) listing upcoming classes.
- **Compensation** (dept_head, `Clients` detail sheet): goodwill wallet credit
  (amount + note) → `POST /clients/compensate`.

New api client methods: `refundClient`, `compensateClient`, `classBookings`,
`markAttendance`, `collectBooking`, plus `payMethod` params on the sale methods.
New types: `PayMethod`, `ClassBooking`, `BookingAttendance`, `BookingPayStatus`.
